# Render.com PORT Configuration Guide

## Issue: "No open ports detected"

Render.com needs the PORT environment variable to be set to detect your server. For Docker deployments, Render.com may not automatically set PORT, so you need to set it manually.

## Solution: Set PORT in Render.com Dashboard

### Step 1: Go to Your Service Settings

1. Log in to [Render.com dashboard](https://dashboard.render.com)
2. Select your backend service: `digital-event-backend`
3. Go to **Environment** tab

### Step 2: Add PORT Environment Variable

Click **"Add Environment Variable"** and add:

- **Key**: `PORT`
- **Value**: `10000`

Click **Save Changes**

### Step 3: Manual Deploy (Optional)

After adding PORT:
1. Go to **Events** tab
2. Click **"Manual Deploy"** → **"Deploy latest commit"**
3. Or just wait for auto-deploy

### Step 4: Verify

Check the deployment logs. You should see:
```
[Server] PORT from environment: 10000
✅ Server running on port 10000
✅ Server bound to 0.0.0.0:10000
```

## Alternative: Use Render.com's Auto-Detection

If Render.com still doesn't detect the port, you can try:

1. **Remove PORT from environment variables** (let Render auto-detect)
2. **Ensure your Dockerfile EXPOSE matches your code's default port**

However, for Docker deployments, **manually setting PORT is recommended**.

## Required Environment Variables Checklist

Make sure these are set in Render.com:

- ✅ **PORT**: `10000` (or any port you prefer)
- ✅ **NODE_ENV**: `production` (should be auto-set)
- ✅ **DATABASE_URL**: Your Supabase connection pooling URL
- ✅ **JWT_SECRET**: Auto-generated by Render (or set manually)
- ✅ **CORS_ORIGIN**: Your frontend URL (e.g., `https://your-app.netlify.app`)

## Troubleshooting

### Still showing "No open ports detected"?

1. **Check if server is actually starting:**
   - Look for `✅ Server running on port...` in logs
   - If you don't see this, the server is crashing before binding

2. **Check for errors:**
   - Look for any error messages in logs
   - Check if database connection is blocking startup

3. **Verify PORT is set:**
   - Check Environment tab in Render dashboard
   - Ensure PORT=10000 (or your chosen port) is listed

4. **Try a different port:**
   - Sometimes port 10000 might be in use
   - Try 8080, 3000, or another port

### Server starts but port not detected?

1. **Check firewall/network:**
   - Render.com should allow connections on exposed ports
   - Verify Dockerfile has `EXPOSE 10000`

2. **Check binding:**
   - Server should bind to `0.0.0.0` (all interfaces)
   - Not `localhost` or `127.0.0.1`

3. **Health check endpoint:**
   - Try accessing `https://your-service.onrender.com/health`
   - If this works, port is open but Render's detection might be delayed

## Quick Fix Command

If you have Render CLI installed:

```bash
render env:set PORT=10000
```

Or use the dashboard as described above.
